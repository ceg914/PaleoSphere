# 테스트 계획과 결과 (v0.2.0)

## 돌리는 방법

```bash
dotnet test tests/PaleoSphere.Tests.csproj              # 자동 테스트 189개
godot --headless --path . -- --selftest                  # 엔진 안 통합 점검
godot --path . --resolution 1600x900 -- --uitest         # UI 통합 점검(창 필요)
tools/check.sh --with-ui                                 # 위 전부
```

내보낸 실행 파일에서도 `PaleoSphere.console.exe --headless -- --selftest`, `-- --uitest`가 같은 점검을 합니다.

## 기기 간 재현성

처음에는 `MathF.Sin`·`Cos`·`Atan2`·`Exp`를 그대로 썼습니다. CI를 붙이자 기준 해시 테스트가 Ubuntu와 Windows 러너에서 모두 실패했는데, 두 러너의 해시는 서로 같고 개발 환경의 해시만 달랐습니다. 운영체제 수학 라이브러리가 CPU에 따라 다른 구현을 골라 마지막 비트가 달라진 것입니다.

코어의 초월 함수를 사칙연산만 쓰는 직접 구현(`src/Core/DetMath.cs`)으로 바꾸자 개발 환경의 해시가 두 러너가 내던 값(`5bc33173a29ce7dc`)과 같아졌습니다. `DetMathTests`는 입력 37개의 결과를 비트 단위로 고정해 두어, 다른 기기에서 값이 달라지면 바로 드러납니다.

남은 조건: 코어에 플랫폼 수학 함수를 다시 들이지 않아야 합니다. `DeterminismGuardTests`가 코어 소스에서 `MathF.Sin`·`Cos`·`Exp`·`Pow` 같은 호출을 찾으면 실패합니다(0.2.0에서 사체 점수에 `MathF.Pow`를 썼다가 이 테스트를 추가하고 제곱근 두 번으로 바꿈). ARM 등 다른 CPU 구조에서는 확인하지 않았습니다.

0.2.0의 기준 해시는 `9801f95ba4426e35`입니다.

## 엔진 안 점검

**셀프테스트(9항목, 초식동물 세계만):** 정의 데이터 읽기(PCK 안의 JSON 포함), 세계 생성·배치, 3000틱 재현성, 섭식으로 식생 감소, 세이브 쓰기·읽기, 불러온 상태 일치, 불러온 뒤 1000틱 일치, 손상 세이브 거부.

**UI 통합 점검(11항목, 초식동물 세계만):** 실제 마우스·키 이벤트를 넣어 확인합니다. 클릭으로 개체 선택, 상세 정보 조회, F 추적, Space 재생, 배치 도구 클릭(30 → 40마리), 교란 도구 클릭 후 도주, Esc로 도구 끄기, 저장, 삭제, 불러오기 후 상태 복원, 불러온 뒤 일시정지.

**포식 화면:** 자동 점검에는 넣지 않았고 스크린샷으로 확인했습니다. `--select-activity=Attack --select-species=tyrannosaurus_rex`로 공격 중인 티라노사우루스를 골라 검사창의 사냥 대상·거리·사냥 성공 수, `--select-activity=Eat`로 사체를 먹는 장면(쓰러진 트리케라톱스 사체, 남은 고기), 60일 뒤 사망 원인 탭의 포식 막대와 개체군 그래프, 이벤트 탭의 사냥 기록을 봤습니다.

## 사람이 직접 확인해야 하는 것

자동 점검이 닿지 않는 부분입니다. Windows에서 실행해 확인이 필요합니다.

1. `PaleoSphere.exe`가 뜨고 한글이 제대로 보이는가.
2. WASD 이동, 우클릭 드래그 회전, 휠 줌이 자연스러운가.
3. `새 세계` 창에서 값을 바꿔 만들기, `저장`·`불러오기` 창의 목록·삭제 버튼, `설정`의 언어·배율 변경.
4. 창 크기를 줄였을 때 패널이 잘리거나 겹치지 않는가(최소 1180×700).
5. 개체 100마리에서의 FPS(`성능 분석` 탭).
6. 한 시간 이상 켜 두었을 때 메모리와 프레임 시간.
