# 변경 이력

## 0.2.0 이후 (같은 버전, 결과는 그대로)

- 0.2.0에서 틱 계산이 0.1.0보다 4분의 1가량 느려졌던 문제를 고침. 개체끼리 밀어내는 계산의 격자 칸 크기를 데이터에 있는 모든 종이 아니라 세계에 있는 개체의 몸집으로 정함. 분리 계산 시간이 0.2.0보다 43% 줄어 0.1.0보다도 빨라짐. 기준 해시와 시나리오 결과는 같음. [PERFORMANCE.md](PERFORMANCE.md)
- Windows 릴리스 빌드에도 콘솔 실행기(`PaleoSphere.console.exe`)를 넣음. 릴리스 빌드에서도 `--selftest`·`--uitest` 결과를 명령 창에서 볼 수 있음

## 0.2.0 — 2026-11-17

Phase 2(생태계 상호작용). 시뮬레이션 버전 0.2.0, 세이브 스키마 2, 데이터 스키마 1(선택 칸 추가). 기준 해시 `9801f95ba4426e35`.

### 구현한 것

- 두 번째 종 티라노사우루스(`data/species/tyrannosaurus_rex.json`). 근거 수준과 출처를 항목마다 적음. Quaternius 리깅 모델(CC0)의 걷기·달리기·공격·죽음 애니메이션 사용
- 사냥: 사냥감 고르기(약하고 가까운 개체), 걸어서 다가가기(잠행), 45 m 안에서 달려들기, 추격 시간·피로 한계, 공격 성공 확률, 실패 시 사냥감 부상과 반격, 추격 포기 뒤 휴지기
- 초식동물의 포식자 회피: 자기를 노리는 포식자, 사냥 중인 포식자, 가까운 포식자를 구분해 공포를 올림
- 사체: 죽은 개체가 남기는 고기와 몸 질량. 육식동물이 냄새로 찾아 먹고, 고기는 상하며, 몸은 분해됨. 질량 장부(생김 = 먹힘 + 분해 + 남음)
- 토양 영양: 분해된 사체의 일부가 둘레 셀에 들어가 식생 성장을 빠르게 하고, 쓰이거나 씻겨 나감. 영양도 누계로 맞춤
- 종 정의에 선택 칸 `predation`(`attack_success`, `defense`, `max_chase_seconds`, `smell_radius_m`). 초식동물에 `attack_success`를 주면 오류
- 시나리오 `predator_introduction`(트리케라톱스 40 + 티라노사우루스 2)
- 세이브 스키마 2: 사체, 질량 장부, 토양 영양, 개체의 사냥 상태. 스키마 1 세이브는 변환해서 읽음
- 화면: 사냥 중 공격 애니메이션, 쓰러진 자세로 남아 분해된 만큼 가라앉는 사체(물가에서 죽으면 수면 바로 아래에 둠), 검사창의 사냥 대상·먹는 사체·사냥 성공 수, 자원 그래프의 사체 고기량, 사건 로그의 사냥 기록, 도감의 포식 관계
- `tools/SimRunner`: 종별 요약, 사체 질량·토양 영양 장부, 여러 종 시나리오
- 스크린샷 인자 `--select-species`, `--search-days`. `--hour`와 `--select-activity`를 함께 주면 낮(8~16시)에 그 동작을 하는 개체를 고름
- 자동 테스트 25개 추가(모두 189개). 포식 시나리오 11개, 코어에 플랫폼 수학 함수가 들어오지 않았는지 보는 검사, 세이브 호환 2개 등

### 측정 결과

`predator_introduction` 120일, 시드 세 개: 트리케라톱스 40마리 가운데 19~23마리 생존, 포식 17~20, 티라노사우루스 2마리 모두 생존. 자세한 표는 [SIMULATION_SPEC.md](SIMULATION_SPEC.md) 13장. 포식자가 없는 기존 시나리오의 결과는 그대로입니다(`lush_lowland` 120일 30/30, `scarce_resources` 3/30).

### 미완성이거나 일부만 된 것

- **번식이 없어 개체 수가 줄기만 합니다.** 포식자를 넣으면 초식동물이 계속 줄고, 오래 돌리면 결국 포식자도 굶어 죽습니다.
- 토양 영양의 효과가 작습니다. 120일 동안 들어온 영양 약 1 t 가운데 성장에 쓰인 것은 30~60 kg입니다.
- 포식 화면은 스크린샷으로만 확인했습니다. 셀프테스트와 UI 점검은 초식동물 세계만 돌립니다.
- 사냥 수치(`attack_success` 0.3, `defense` 0.35 등)는 결과가 그럴듯해지도록 맞춘 값이고 근거가 없습니다(`simplified`로 표시).
- 모델 파일이 없을 때 쓰는 대체 메시는 네 발 형태라, 티라노사우루스도 네 발로 그려집니다.
- Windows 실행 확인은 여전히 안 됐습니다.

### 개발 중 고친 문제

- 포식자가 깊은 물 건너편 사체로 가려다 얕은 물에 갇혀 굶어 죽던 문제. 물속에서는 쉴 수 없어 피로까지 쌓였습니다. 사냥감·사체를 고를 때 직선으로 걸어갈 수 있는지 검사하고, 오래 다가가도 닿지 못한 사체는 무시하도록 고쳤습니다.
- 사체 하나가 토양 영양을 수 톤씩 만들던 문제. 영양으로 돌아가는 비율을 30%에서 1%로, 성장 효과가 절반이 되는 영양량을 20 kg에서 5 kg으로 낮췄습니다.
- 포식자 두 마리가 120일 동안 40마리 가운데 26~27마리를 잡던 문제. 사냥에 나서는 에너지 기준을 0.7에서 0.55로, 고기가 상하는 속도를 하루 20%에서 10%로 낮춰 17~20마리가 되었습니다.
- 같은 틱에 이미 처리를 마친 개체가 뒤 순서의 포식자에게 죽으면 목록에서 빠지지 않던 문제.
- 사체 점수 계산에 `MathF.Pow`를 써서 기기 간 재현성이 깨질 수 있던 문제. 제곱근 두 번으로 바꾸고 재발을 막는 테스트를 넣었습니다.

### 0.1.0 이후 (같은 버전, 표현 계층만 변경)

- 트리케라톱스를 Quaternius의 리깅 모델(CC0)로 교체. 대기·걷기·달리기·죽음 애니메이션을 쓰고, 걷기·달리기 재생 속도를 실제 이동 속도에 맞춰 발이 미끄러지지 않게 함. 원본에 없는 먹기·마시기(고개 숙이기)와 쉬기(다리 접고 엎드리기)는 뼈 보정(`CreatureRigModifier`)으로 만듦. 죽은 개체는 쓰러지는 동작을 재생한 뒤 땅으로 가라앉음
- 모델 파일이 없거나 불러오지 못하면 코드로 만든 메시로 자동 대체
- 지형 셰이더 재작성: 셀 격자 무늬 제거(월드 좌표 노이즈), 생물군계 경계 흐트러뜨리기, 급경사 바위색, 물가 진흙띠, 잔결 법선
- 물 셰이더: 깊이에 따른 색, 잔물결, 물가 거품
- 지피 식생(양치류·속새·덤불)을 64 m 타일 단위로 깔고, 셀의 식생량에 따라 크기가 줄어들게 함(먹힌 자리가 듬성해짐). 190 m 밖은 그리지 않음
- 원뿔 나무를 침엽수·활엽수·소철류 메시로 교체. 백악기 후기에 넓게 퍼지지 않았던 풀밭은 만들지 않음
- 모델 측정 도구: `tools/godot/inspect_model.gd`, `measure_model.gd`, `measure_gait.gd`, `bone_tree.gd`
- 개체 모델을 캡슐·상자 조합에서 코드로 만든 메시로 교체. 단면을 이어 붙인 몸통과 꼬리, 프릴과 뿔 세 개가 붙은 머리, 무릎이 굽는 두 마디 다리, 등은 어둡고 배는 밝은 색. 시뮬레이션 결과에는 영향이 없습니다(기준 해시 그대로).

### 미완성이거나 일부만 된 것

- **Windows에서 실행해 보지 못했습니다.** 내보내기는 성공했고 같은 내용의 Linux 실행 파일은 동작합니다. Wine 9.0에서는 공식 Godot 4.7.2 Windows 템플릿 자체가 시작 직후 죽어 대신 확인할 수 없었습니다.
- **FPS를 재지 못했습니다.** GPU가 없는 환경이었습니다.
- 개체 모델은 양식화된 로우폴리이고 피부 질감이 없습니다. 먹기·쉬기 자세는 원본 애니메이션이 아니라 뼈 보정이라 다소 어색할 수 있습니다.
- 일반 경로 탐색(A*)이 없습니다.
- 사망 원인 그래프는 시계열이 아니라 누계입니다.
- CSV 내보내기는 `tools/SimRunner --csv`에만 있습니다.
- 영어로 바꿔도 종·생물군계 설명문은 한국어로 나옵니다.
- 배포 시 필요한 Godot·제3자 라이선스 고지 화면이 없습니다.
- 카메라 조작과 대화상자의 버튼은 사람이 직접 눌러 확인하지 못했습니다(프로그램 경로만 점검).
- 종 정보의 정확성을 전문가가 검토하지 않았습니다.

### 구현하지 않은 것

육식동물·포식, 번식, 성장·노화, 사체·분해, 지형 편집기, 날씨·가뭄·수자원, 무리 행동, 기억, 감각 모델, 형질 유전, 히트맵, A/B 실험 비교, 사진 모드, 모드 데이터팩 적재, 튜토리얼, 설치 프로그램.

### 개발 중 고친 문제

- 같은 시드인데 기기마다 결과가 달라지던 문제. CI의 Ubuntu·Windows 러너와 개발 환경의 기준 해시가 달랐고, 원인은 운영체제 수학 함수의 기기별 구현 차이였습니다. 코어의 초월 함수를 직접 구현으로 바꿔 세 환경의 해시를 맞췄습니다.

- 식생이 75% 남았는데도 개체가 굶어 죽던 문제. 강가의 개체가 건널 수 없는 건너편 먹이를 계속 목표로 잡은 것이 원인이었고, 목표를 정할 때 직선으로 걸어갈 수 있는지 검사하도록 고쳤습니다.
- 주변 식생을 다 먹은 뒤에도 자리를 옮기지 않고 부스러기만 찾던 문제. 주변이 빈약하면 멀리 옮겨 가도록 했습니다.
- 건조한 세계에서 섭식 기준이 높아 아무것도 먹지 못하던 문제. 기준을 세계의 평균 수용량에 맞췄습니다.
- HUD가 화면 왼쪽 위에 뭉치던 문제(앵커만 바꾸고 오프셋을 그대로 둔 탓).
- Godot가 요구하는 솔루션 파일이 없어 .NET 내보내기가 실패하던 문제.
